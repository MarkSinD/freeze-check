# freeze-check: какие хостинги работают из России

**Полный разбор (на английском): [REPORT.md](REPORT.md).** Русская версия — статья на Хабре.

[English](README.md)

С 2025 года оборудование ТСПУ «замораживает» TCP-соединения с частью зарубежных хостингов.
Соединение открывается, проходит несколько пакетов (около 8 на мобильном интернете, около 25 на
домашнем проводном), а дальше данные не идут, и сброса тоже нет. Сайт «долго грузится, потом
ошибка», VPN на TCP (Reality, XHTTP, OpenVPN TCP) не подключается, а UDP (WireGuard, AmneziaWG)
работает.

Этот инструмент за 2–4 минуты показывает, какие сети замораживаются **с вашего подключения**, и
проверяет ваш собственный сервер.

- Около 430 точек примерно в 200 сетях: публичные тестовые файлы хостингов, проверены из Европы.
- Нужны только `bash` и `curl`: Linux, macOS, Git Bash в Windows.
- Ничего никуда не отправляется. В файле результатов нет вашего IP. ipinfo.io спрашивается только
  страна (чтобы предупредить о включённом VPN) и, для `owner`, данные об адресе, который вы дали.

## Скачать

```bash
mkdir freeze-check && cd freeze-check
curl -fsSLO https://raw.githubusercontent.com/MarkSinD/freeze-check/main/freeze-check.sh
curl -fsSLO https://raw.githubusercontent.com/MarkSinD/freeze-check/main/targets.tsv
```

Или скачайте ZIP на GitHub (Code → Download ZIP). Скрипт короткий: прочитайте его перед запуском.

## Проверить с компьютера

VPN нужно выключить, иначе вы проверите сеть VPN-сервера, а не свою. Проще всего запустить с
`--wait` и выключить VPN уже после запуска: скрипт дождётся российского адреса и начнёт сам.

```bash
bash freeze-check.sh scan --quick --wait
```

`--quick` проверяет одну точку на сеть, около 30 секунд. Без него проверяются все точки, 2–4 минуты.
Результат сохраняется в папку `results/` рядом со скриптом, в конце скрипт пишет, что VPN можно
включать. Чтобы подписать замер: `--label "Билайн LTE, Москва"`.

Обычные сайты на Cloudflare и других CDN (каждый адрес 3 раза):

```bash
bash freeze-check.sh cdn --wait
```

Начало вывода на нашем домашнем интернете (ноябрь 2026):

```text

BLOCKED networks (17) - every point there failed:
  AS16276   OVH SAS                            12/12  BlueVPS, IPhoster, KarasHost, OVH, SadeemRDP, ThomasHost
  AS63023   GTHost                             11/11  Qyrax
  AS36352   HostPapa                             7/7  DediRock, HostNamaste, RackNerd, SadeemRDP, Server Wala, SolaDrive

```

- `FROZEN`: соединение открылось и встало на нескольких килобайтах. Это заморозка.
- `NONE`: не пришло ничего. На мобильном это обычно та же заморозка: порог меньше TLS-рукопожатия.
- `SLOW`: данные идут, но медленно. Это не заморозка.
- В конце выводятся точки, где ваш результат отличается от нашего ноябрьского замера.

**Поделитесь результатом.** Откройте [форму на GitHub](https://github.com/MarkSinD/freeze-check/issues/new?template=freeze-check-result.yml): оператор, регион, дата и вывод
скрипта, без IP. Так таблица перестаёт быть замером одного человека.

## Проверить свой сервер

Узнать, в чьей сети стоит сервер, и что мы там намерили:

```bash
bash freeze-check.sh owner your.server.example
```

Замерить сам сервер. **На сервере** (нужен `python3`, порт открыть в файрволе):

```bash
bash freeze-check.sh serve 8080
```

Скрипт напечатает адрес тестового файла. **На компьютере в России, с выключенным VPN:**

```bash
bash freeze-check.sh url --wait http://ВАШ_СЕРВЕР:8080/<токен>/freeze-test.bin
```

Или откройте этот адрес в браузере телефона. Проверьте тот же адрес и из-за границы: если там
скачивается, а из России встаёт, это заморозка. Остановить сервер: Ctrl+C, файл удалится сам.
Порт 80 не берите: часть операторов его перехватывает.

## Что делать, если ваш сервер заморожен

1. **Проверьте, в чьей сети сервер** (`owner`). Решает владелец сети, а не бренд хостинга. Дешёвый
   хостинг, который стоит в сети OVH, M247 или HostPapa, заморожен так же, как сама сеть.
   Заморожена вся компания: у Hetzner в США и Сингапуре отдельные номера сетей, и они заморожены
   так же, как в Европе.
2. **Подтвердите замером** (`serve` и `url`): из России встаёт, из-за границы скачивается.
   Сравните мобильный и домашний интернет.
3. **Срочно: поднимите UDP.** WireGuard или AmneziaWG на том же сервере обычно продолжают
   работать: заморозка бьёт по TCP. Это временная мера, а не решение.
4. **Не тратьте время** на смену IP у того же провайдера, смену порта или протокола поверх TCP.
   Новый адрес будет в той же замороженной сети, порт роли не играет.
5. **Переезжайте в сеть, которая проходит.** Выбирайте по замеру (`scan`, затем `owner` для
   кандидата), а не по цене и отзывам. Почасовая оплата позволяет проверить сервер за копейки до
   переезда.
6. **Держите запас в другой сети.** Второй сервер у другого владельца сети: списки меняются, и
   работающая сегодня сеть может попасть под заморозку завтра.
7. **Перепроверяйте** раз в неделю или две: `scan --quick` занимает полминуты.

Короткие соединения тоже проходят: счётчик пакетов считается на одно соединение. Но порог в ~8
пакетов на мобильном слишком мал, чтобы строить на этом надёжную связь.

## Как это измерено

Сырые обезличенные прогоны за ноябрь 2026: [`data/2026-11`](data/2026-11).

- Каждая точка: одно соединение, нужно скачать 256 КБ. Список целей и наши результаты лежат в
  [`targets.tsv`](targets.tsv): колонки `home_ru` (домашний проводной) и `mobile_ru` (Билайн LTE),
  05–06.11.2026.
- Контроль: тот же список скачивается из Европы. Точки, которые не скачались оттуда, исключены.
- Механика (пакеты, а не байты; счётчик на соединение; без RST) получена записью пакетов на
  сервере в замороженной сети.
- Ограничения: тестовые файлы хостинга могут стоять не в той подсети, что обычные VPS. Точка, где
  не скачалось только одно место, может быть просто мёртвым тестовым сервером. Результаты разных
  операторов и регионов могут отличаться.
